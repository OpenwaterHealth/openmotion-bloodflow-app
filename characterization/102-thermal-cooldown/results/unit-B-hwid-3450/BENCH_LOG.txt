--- E1b/E2b repeat + powered-vs-rails-off cooldown comparison (appended by hand) ---
E1b heat run: clean, no errors, no camera latches (deaths.py: 16/16 rows, no deaths,
32 total cumulative across E1a+E1b).
E2b (rails-off, cycled off/on every ~120s to sample, capture-before-read) cooldown_fit:
T_floor_c 35.9-46.1C per camera, tau up to 8.8 min, several cams' fits NaN (too
plateaued/noisy near their floor for a clean exponential fit).
Compare to E2a (rails stayed powered continuously, sampled every 5s, no cycling):
T_floor_c 24.6-31.8C per camera, tau 4.7-8.5 min.
And to the one-off true rails-off test before E1a (fully off 5 min, zero polling,
single read after): all 16 cams 20.7-27.6C.

Conclusion: cycling rails off/on to sample (E2a's cold-gate mode and E2b) plateaus
10-15C HIGHER than leaving rails continuously powered, which itself sits a few C
above a true uninterrupted rails-off cooldown. The periodic re-power (plus the
forced capture-before-read frame) reintroduces a power-on thermal transient each
cycle and the tool samples inside that transient rather than a settled rails-off
temperature. This is a measurement-method artifact of thermal_logger's rail-off
mode, not a real property of the hardware -- the camera's true rails-off floor is
close to ambient (~21C room temp) per the manual test. Recommend future rails-off
gating/characterization use a single off-period-then-read (as done manually here)
rather than periodic re-power-to-sample, if a true rails-off floor is needed.
